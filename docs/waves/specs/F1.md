# F1 Configuration et secrets

## Summary

Toute la configuration de l'application passe par des variables d'environnement, déclarées et validées au démarrage : secrets obligatoires sans défaut, fuseau horaire, SMTP et sources de suggestions facultatifs. Le fichier `.env.example` est complet et commenté. Cette fonctionnalité est la plus petite brique du socle et ne dépend de rien.

## In scope

- Module Go `secretsanta` (version stable récente de Go, épinglée dans go.mod et dans le Dockerfile). Arborescence : `cmd/secretsanta/` (point d'entrée), `internal/<module>/` (un paquet par fonctionnalité métier), `internal/app/` (assemblage), `web/` (templates et assets embarqués). Les tests Go vivent à côté du code (`internal/<module>/*_test.go`). Les tests d'affichage mobile Playwright vivent dans `tests/e2e/<fonctionnalité>/` ; Playwright est un outil de développement uniquement : son `package.json` est confiné à `tests/e2e/` et n'entre jamais dans l'image.
- Configuration : toutes les variables d'environnement du projet sont déclarées et validées ici (instance, secrets, fuseau, SMTP, relances, sources de suggestions), avec un `.env.example` complet et commenté. Les secrets obligatoires (mot de passe d'instance de création de groupe, secret de signature) n'ont aucun défaut : l'application refuse de démarrer sans eux, avec un message clair en français. Fuseau en variable, défaut Europe/Paris. Le SMTP et les sources de suggestions sont facultatifs (leur absence désactive la fonction, elle n'empêche pas le démarrage).
- Variables de courrier pour la délivrabilité : `MAIL_EHLO_HOSTNAME` (nom d'hôte annoncé à EHLO, nom de domaine plein ou adresse entre crochets), `MAIL_ENVELOPE_FROM` (expéditeur d'enveloppe ; par défaut l'adresse d'expédition), `MAIL_REPLY_TO` (facultatif), `MAIL_TLS_MODE` (`starttls` par défaut, `tls` pour le TLS implicite, `none`), `MAIL_ALLOW_INSECURE` (faux par défaut ; le mode `none` est refusé au démarrage tant qu'il n'est pas explicitement à vrai, de sorte que le chiffrement est exigé par défaut), `MAIL_MAX_PER_MINUTE` et, pour la signature DKIM facultative faite par l'application, `MAIL_DKIM_DOMAIN`, `MAIL_DKIM_SELECTOR`, `MAIL_DKIM_KEY_FILE` (chemin d'un fichier ; la clé privée n'est jamais acceptée en clair dans une variable d'environnement), `MAIL_DKIM_ALGORITHM` (`rsa-sha256` ou `ed25519-sha256`) et `MAIL_DKIM_HEADERS` (liste des en-têtes signés, défaut raisonnable). Une configuration DKIM incomplète est refusée au démarrage avec un message français. Aucun secret (mot de passe SMTP, chemin ou contenu de clé) n'apparaît dans les journaux ni dans les messages d'erreur.

## Out of scope

- Base de données et ports partagés (F1b), point d'entrée, gabarits web et livraison (F1c).
- Toute logique métier.

## Acceptance criteria

```yaml criteria
AC1: {text: "Le démarrage échoue avec un message français nommant la variable manquante quand le mot de passe d'instance ou le secret de signature est absent, et réussit quand ils sont fournis", verify: "test:internal/config/config_test.go"}
AC2: {text: "Le fuseau vaut Europe/Paris par défaut et toute valeur de fuseau invalide est refusée au démarrage", verify: "test:internal/config/timezone_test.go"}
AC3: {text: "Toutes les variables lues par le code figurent dans .env.example et inversement", verify: "test:internal/config/env_example_complete_test.go"}
AC4: {text: "Les variables de courrier de délivrabilité ont des défauts sûrs (TLS en starttls, expéditeur d'enveloppe égal à l'adresse d'expédition) ; le mode TLS none est refusé au démarrage sans MAIL_ALLOW_INSECURE explicite, un nom EHLO invalide est refusé et chaque refus nomme la variable en français", verify: "test:internal/config/mail_delivery_config_test.go"}
AC5: {text: "La signature DKIM n'est acceptée que complète (domaine, sélecteur, chemin de fichier lisible, algorithme rsa-sha256 ou ed25519-sha256) ; une clé privée fournie en clair dans une variable, un fichier illisible ou un algorithme inconnu sont refusés au démarrage", verify: "test:internal/config/dkim_config_test.go"}
AC6: {text: "Aucune valeur secrète (mot de passe SMTP, clé DKIM) n'apparaît dans la représentation texte de la configuration, les journaux de démarrage ni les messages d'erreur", verify: "test:internal/config/secrets_redaction_test.go"}
```

## Steps

- F1.1 Écrire la configuration validée (variables d'environnement, secrets obligatoires sans défaut, fuseau, SMTP et sources facultatifs) avec `.env.example` complet et leurs tests.
- F1.2 Variables de courrier et de signature DKIM (TLS exigé par défaut, EHLO, expéditeur d'enveloppe, débit, clé par fichier) validées au démarrage avec masquage des secrets et leurs tests.
