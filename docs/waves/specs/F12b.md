# F12b Parcours de bout en bout, couverture et contrôles de livraison

## Summary

Cette fonctionnalité transforme les fonctionnalités construites en un livrable vérifié : parcours Playwright complets joués contre l'image réellement construite, couverture de test mesurée par paquet avec seuils, contrôle de l'image (taille, non-root, sans shell, healthcheck), recherche de vulnérabilités, workflows de recette et de couverture. Un défaut révélé est corrigé dans la fonctionnalité qui possède le code, jamais contourné ici.

## In scope

- **Parcours de bout en bout** (`tests/e2e/journey/**`, numérotés) : (01) création du groupe protégée par le mot de passe d'instance, activation du lien d'invitation, inscription d'une personne par lien avec code lu dans le serveur factice, validation sans code par l'admin d'une autre ; (02) lettre au Père Noël avec idées, saisie des foyers et exclusions, budget laissé vide puis défini ; (03) tirage, contrôle du tirage sans noms, révélation (les trois styles forcés l'un après l'autre par la graine de test), cible et lettre reçue ; (04) ajustement après tirage (retrait puis ajout) avec courriels vérifiés dans le serveur factice, nouvelle règle contredisant une paire, relance manuelle ; (05) désinscription par lien signé, admin sans vue des paires, isolation entre deux groupes ; (06) sauvegarde de la base puis restauration dans un conteneur neuf, conformément à la procédure du README.
- **Relances automatiques** : leur déclenchement à 3 puis 7 jours est prouvé par les tests unitaires à horloge simulée de F7 ; la recette conteneur n'expose aucun point de déréglage de l'horloge (pas de porte dérobée de test dans l'image) et ne joue que la relance manuelle.
- **Couverture** (`scripts/coverage.sh`) : `go test` avec profil de couverture (statements) ; seuils ≥ 80 % par paquet `internal/*` (hors `internal/app`, câblage couvert par les parcours) et ≥ 85 % pour `internal/draw`. Avec `--enforce` le script échoue sous les seuils ; sans, il imprime le tableau et n'échoue pas. Les trous de couverture sont comblés par des tests ajoutés dans `internal/<paquet>/zz_coverage_*_test.go` (fichiers réservés à cette fonctionnalité), jamais en modifiant le code ou les tests des autres fonctionnalités.
- **Contrôles de l'image** (`scripts/check-image.sh`) : taille ≤ 40 Mo (mesurée, valeur affichée), utilisateur non root, aucun shell dans l'image, healthcheck déclaré et vert, binaire statique, conteneur qui refuse de démarrer sans les secrets obligatoires.
- **Sécurité des dépendances** (`scripts/check-vuln.sh`) : `govulncheck ./...` et rapport des alertes ; échec si une vulnérabilité atteignable est trouvée.
- **CI** : `.github/workflows/coverage.yml` produit le rapport de couverture comme artefact sans bloquer la publication de l'image ; `.github/workflows/recette.yml` rejoue la recette complète sur `linux/amd64` dans GitHub Actions sans publier. Ces fichiers sont distincts du workflow de publication de F1, qui reste la seule source des tags et de la rétention.
- Parcours supplémentaires : (07) rôles dans le tirage : l'administrateur règle les rôles par le panneau « Rôles dans le tirage », le tirage avec une personne `reception_seule` donne deux cibles à un tireur `offre_plus`, la révélation des deux cibles se joue en séquence avec des styles différents, les deux lettres se lisent, la personne `reception_seule` voit son accueil, un changement de rôle après le tirage passe par l'aperçu en comptes sans nouveau tirage ; (08) délivrabilité : la page de diagnostic s'affiche dans le conteneur avec ses points à corriger, sa section « non vérifiable ici » et les en-têtes du courriel de test, et une adresse refusée par le serveur factice apparaît dans la liste de suppression.
- Score antispam : `scripts/spamcheck.sh` (F12a) note chaque modèle de courriel (les `.eml` de référence de F6) et les messages capturés pendant les parcours, avec un seuil inférieur à 3,0 ; la sortie rappelle que cela mesure le contenu et non la réputation de l'IP.
- Le parcours est aussi joué en anglais (cookie `lang=en`) sur les écrans principaux, et une langue ajoutée par un fichier plat dans `I18N_DIR` apparaît dans le sélecteur sans reconstruire l'image.

## Out of scope

- Banc de recette et documentation (F12a).
- Toute modification fonctionnelle ou de design.
- La publication de l'image et la rétention des versions (F1c), les tests de charge et la vérification de l'image linux/amd64 sur le Mac.
